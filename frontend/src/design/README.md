# 设计参数

侧栏（以及它上面那几个自绘控件）的设计参数集中在这里。
代码里能引用的参数写成 `.ts`，只能由 CSS 表达的参数写在本文件里。

```
design/
  icons.ts    四个导航按钮的图标路径 + 统一的视图框 / 渲染尺寸
  glass.ts    液态玻璃的折射参数（SVG 位移滤镜）
  morph.ts    「更多」按钮**旧版形变动画**的几何常量（归档，见文末）
  README.md   尺寸 / 间距 / 动效口径 —— 为什么是这些值，以及真正落在哪
```

---

## 侧栏是一列四个等权按钮

`首页 / 功能 / 联系 / 更多` 是**四个页面**，地位完全相同，都在指示条队列里。
「更多」不是弹出菜单 —— 站名、时段与身份、管理后台、退出登录都放在它那一页。

### 两个参数：一个管宽度，一个管其余一切

侧栏的尺寸被反复微调过（收窄 → 溢出加大 → 整体 +5% → 再放大 → 加宽），
逐个数手算既容易漏、又让「等比」变成近似。所以定成：

```css
/* .shell */
--sidebar-scale: calc(48 / 42);   /* 胶囊 / 间距 / 溢出 / 面板高度 */
--sidebar-width: 58px;            /* 面板实宽，**独立** */
```

- `--sidebar-scale` 的基准值都是**倍率 = 1 时**那一版（面板宽 42px），
  CSS 里一律写成 `calc(基准值 * var(--sidebar-scale))`。
  「整体等比放大」= 只改这一个数，不会漏掉某处，也不会近似。
- `--sidebar-width` 写成「上一个宽度 + 增量」，让改动可追溯。
  ⚠️ **它已经和倍率解耦**：一旦胶囊尺寸要「不变」而面板要「变宽」，
  两者就必须分开，否则挂在一起的量会一起走。

当前：倍率 `≈ 1.1429`、面板实宽 **`58px`**。

| 量 | 值 | 出处 |
|---|---|---|
| 侧栏列宽 | `calc(24px + var(--sidebar-width))` | `.shell` |
| 侧栏左边距 | `24px`（`--space-lg`） | `.sidebar { margin: … 0 … var(--space-lg) }` |
| **面板实宽** | **`58px`** | 列宽 − 24 |
| 胶囊宽 | `calc(60px * var(--sidebar-scale))` = **`68.57px`** | 绝对值，**不挂 `100%`** |

面板左右 `padding` 必须是 `0` —— 这是胶囊能溢出面板的前提（见下）。

### 设计目标：图标到「面板边缘」要**小于**到「胶囊边缘」

这是本控件被反复微调后收敛出来的判据 —— 两边相等也不好：

| 面板宽 | 面板边缘 → 图标 | 胶囊边缘 → 图标 | 读起来像 |
|---|---|---|---|
| `48px` | `12px` | `22.29px` | 面板边缘**贴着**图标、「太近」 |
| `68px` | `22.29px` | `22.29px` | 两者**等宽**，糊成一片、读不出「一列按钮浮在轨道上」 |
| **`58px`** | **`17px`** | **`22.29px`** | 面板比胶囊窄，结构清楚 |

图标在面板里居中、也在胶囊里居中，所以两个距离都由面板宽 / 胶囊宽直接决定。
目标不是「相等」，而是让面板**明显窄于胶囊**（现在窄 `10.6px`）。

这也是为什么胶囊宽度**不能**写成 `calc(100% + …)`：那样面板一加宽，胶囊跟着加宽，
两个边距会同时变大，比例关系永远不变、问题只是被放大。

### 溢出量

面板 `68` / 胶囊 `68.57` —— 两者几乎等宽，所以**左右方向的「溢出」已经归零**
（差 `0.57px`，可忽略）。上下方向仍各溢出 `10.28px`（由 `.sidebar__nav` 的负外边距给出）。

> 历史：早先四边溢出各 `4px`（`4` vs 顶端 `16.7`，观感不一致，实测**根本看不出来**），
> 后来统一放大到四边各 `9px`。现在的「左右零溢出」是为了满足上面那条**等距**判据
> 而**主动放弃四边相等**的结果。

| 量 | 基准值 | 说明 |
|---|---|---|
| 胶囊 × 4 | `60 × 75.6px` | 高 > 宽 ⇒ `border-radius: 999px` 被限死成 34.3px，上下各成半圆、左右留直线段，成为**竖向胶囊**。宽度写成**绝对值**（`60px × 倍率`），不挂 `100%` |
| 胶囊间距 | `8px` | 触控目标最小间隔（ux-guidelines: Touch Spacing） |
| 面板纵向内边距 | `6px` | 只留 6px：剩下的交给负外边距 |
| 导航列负外边距 | `-15px`（上下） | `15 = 6px 内边距 + 9px 上下溢出` |

### 图标**不**参与缩放

图标大小是单独定的参数，与侧栏几何解耦：侧栏放大时图标保持原样
（当前选中 `24px`、未选中 `24 × 1.2 = 28.8px`）。
所以 `.sidebar__btn svg` 的尺寸**不乘** `--sidebar-scale`。

| 量 | 值 | 约束 |
|---|---|---|
| 图标基准尺寸 | `24px` | **选中态**的尺寸 |
| 图标倍率 | 未选中 **`×1.2`** | 选中时回到 `×1`。图标「收」进去的同时胶囊「弹」出来，两个方向一起动才有「选中」的力度 |

侧栏总高与内边距无关，只由堆栈与溢出去定：

```
面板高 = 胶囊堆栈 − 上下溢出量×2
       = (4 × 75.6 + 3 × 8 − 2 × 9) × scale
       = 308.4 × 1.1429
       = 352.4px
```

面板 `68 × 352.4`（长宽比 `5.18`）。注意：

- **高度**随倍率走（`--sidebar-scale`），**宽度**不跟随（`--sidebar-width` 独立）——
  这是本轮「只加宽、其余不变」的要求所决定的。
- 高度与 `padding-block` 无关：`面板高 = 2P + (堆栈 − 2(P+O)) = 堆栈 − 2O`，
  `padding` 加多少负外边距就抵消多少，所以它只能改「胶囊离面板边多远」。

### 为什么按钮只剩图标

面板收窄后，两个字（15px × 2 = 30px）加两侧呼吸已经贴边，再加入第四个按钮
就必然溢出。改成图标后标签换了一条路可读：`aria-label` 给屏幕阅读器、`title` 给鼠标用户
（ux-guidelines 把「icon-only button without label」列为反模式），两者都取 `SECTIONS` 里的中文标签。

## 图标选型

依据 `ui-ux-pro-max`（`--domain icons`，Phosphor Outline 一族）：
Outline 风格、控件用 20–24px。本项目不引入图标库——四个图标自绘，
渲染口径与功能卡片图标一致（24 视图框 / 只描边 / `stroke-width: 1.7` / 圆头端点）。

选型的硬指标是**外轮廓可分辨**，四个剪影刻意拉开：

| 按钮 | 剪影 | 说明 |
|---|---|---|
| 首页 | 尖顶 | 屋顶 + 两墙 + 门 |
| 功能 | 四块 | 2×2 圆角方块；间距 4 单位是下限，再挤描边会糊成一块 |
| 联系 | 横长方形 | 信封 + 封口 |
| 更多 | 横向三点 | 半径 0.85 配 1.7 的描边 = 直径 3.4 的实心点，与归档的形变起点同形 |

## 液态玻璃（iOS 27）

> **当前状态**（多轮实测后收敛到的形态）：面板**完全隐形** ——
> 不铺底色、不磨砂、不投影、不画描边。可见的只有两样：
>
> 1. **胶囊按钮**自己的玻璃：白膜 + 描边 + 顶部内高光 + 底部内反光 + 投影；
> 2. **光标光晕**：鼠标扫过时沿面板轮廓亮起一圈，且被胶囊挖洞。
>
> 下面几节记录的是**为什么走到这一步**和各机制的原理。其中折射（§1）与
> 主题色光晕（§2）**当前无调用方**，参数都留着（`glass.ts`、`LiquidGlassDefs`、
> `--accent-soft`），接回来是一行的事。§3 的壳现在只作为光晕的载体存在。
>
> 收敛过程按顺序记录了四条被排除的假设：白膜（`background`）、
> 饱和度（`saturate`）、彩色光晕（`--accent-soft`）、以及最后定位到的
> **壳上的静态描边在上下半圆处残留的两段白弧** —— 详见 `DESIGN-LOG.md`。

液态玻璃跟普通毛玻璃（glassmorphism）的区别在于它**不只是模糊背景**。三件事一起做才成立：

### 1. 折射 —— 对背景的形变

背景透过玻璃时被「厚薄不均」的玻璃挤歪，这是「液态」的来源。
Web 上只能靠 SVG 滤镜：`feTurbulence` 生成一张**低频**噪声当位移图，交给 `feDisplacementMap`
去挤 `SourceGraphic` —— 在 `backdrop-filter` 里它就是**元素背后的画面**，所以是真形变。
参数全在 `glass.ts`：

| 量 | 值 | 理由 |
|---|---|---|
| `baseFrequency` | `0.012 0.022` | 频率要低。一高就变成「磨砂颗粒」，不是玻璃的厚度起伏 |
| `numOctaves` | `2` | 再多只涨开销，看不出差别 |
| `seed` | `11` | 固定住，否则每次刷新折射的花纹都不一样 |
| `smoothing` | `3` | 位移场不连续的话背景会被切成一格一格，而不是被「挤」 |
| `scale` | `10` | 最大位移 = `scale/2` = 5px。对 48px 宽的面板，是「看得出在挤、但还读得出字」的量级 |
| 滤镜区域 | 外扩 30% | 形变会把边缘外的背景拉进来，不外扩就会在边界切出一条硬边 |

CSS 里写成**两条**声明，顺序要紧：

```css
backdrop-filter: blur(var(--blur));                    /* 回退 */
backdrop-filter: url(#liquid-glass) blur(10px);        /* 增强 */
```

- 不认 `url()` 的浏览器会丢掉第二条、用第一条 —— 退化成普通毛玻璃，**而不是整条失效变全透明**。
- 带 `url()` 的那条把模糊从 18px 降到 **10px**：折射已经把背景打散了，再叠 18px 就等于把形变糊没。
- **两条都不带 `saturate`。** 这是逐步摸出来的：`saturate` 不像模糊那样只把颜色平均化，
  而是直接把背景的**饱和度拉高**（原先 `190%`）。深色背景下 `rgb(29,30,47)` 这种灰蓝
  会被推成明显的紫蓝，整条面板看上去就「自带一层底色」。
  面板要不改色，只做形变与虚化。

### 2. 光晕

外缘两圈，纯 CSS：

```css
0 0 0 1px rgba(255, 255, 255, 0.14),   /* 极淡白边 */
0 0 46px -6px var(--accent-soft);      /* 取自主题色的柔光 */
```

负扩散（`-6px`）把光收在元素附近，否则会糊成一片而不是一圈。主题光晕用 `--accent-soft`，
于是它会跟着 `.glass` 那条 `box-shadow 4s linear` 一起，随一天中的时段平滑变色。

### 3. 厚度 —— 壳必须单独画，而且要被胶囊挖个洞

描边不用 `1px` 硬边框（会在半圆与直线的衔接拐点露出折角），改成 inset 三层：
玻璃边 + 顶部内高光 + 底部内反光。

但这三层**不能画在面板本体上**：胶囊比面板大一圈，当胶囊跨过面板轮廓时，
那圈 1px 框线会从胶囊**内部**穿过去，看着像「胶囊里套了个边栏的框」。

正确做法不是在描边上“抠”一条线段，而是：**面板本体只留背景与折射，
另起一层 `.sidebar__edge` 專画壳，并用一个与胶囊同形、同位的洞把它挖掉**。
不需要求轮廓交点 —— **形状本身就是答案**。

```css
.sidebar__edge {
  /* 洞 = 一个 rx/ry 都是 50% 的矩形，拉伸到胶囊尺寸后就是胶囊本身。
     preserveAspectRatio='none' 是关键：没有它，矩形会等比缩放、变成圆 */
  --hole: url("data:image/svg+xml,…%3Crect rx='50%' ry='50%'/…");

  mask-image: linear-gradient(#000 0 0), var(--hole);   /* 全层 减 洞 */
  mask-size: 100% 100%, var(--cut-w) var(--cut-h);
  mask-position: 0 0, var(--cut-x) var(--cut-y);
  mask-composite: exclude;
  -webkit-mask-composite: xor;
}
```

`--cut-*` 由 `Sidebar` 用 **GSAP 与指示条同一条曲线、同一时刻**写入 ——
否则洞会跟不上胶囊，滑动途中会露出半截断口。
默认 `--cut-w/h` 为 `0`，即洞不存在、壳完整可见，所以不会首帧闪一下。

**为什么不用 `clip-path: inset()` 切两条水平带**：那需要知道「面板轮廓被胶囊盖住的 y 范围」，
而它就是两条轮廓线的交点。面板轮廓在上/下端点处是**半圆弧**，胶囊端是**半椭圆弧**，
交点要解方程组；而且解出来的结果对首尾两个按钮与中间两个按钮还不一样
（首尾时整个半圆都落在胶囊内 —— 无交点）。用形状挖洞那么这些几何全部免了。

投影与光晕仍留在面板本体上：它们会「透」进胶囊里，但那是对的 ——
投影本来就落在胶囊下方。切掉的只是硬描边。

**光标光晕也得跟着壳走。** 否则它会沿着面板那条**完整的**胶囊边描一圈，
而那条边已经被胶囊按钮盖住了 —— 描的是一条看不见的线。
做法：`.sidebar__edge::after` 与其它玻璃件共用同一套光晕样式，
桌面端把 `.sidebar::after` 关掉（`content: none`）。

两个细节：

- `--glow` / `--glow-x` / `--glow-y` 是 `useCursorGlow` 写在 `.sidebar` 上的，
  壳作为它的子元素会**继承**下来；两者 `inset` 都是 0、尺寸完全相同，
  所以百分比坐标含义也一致，**不需要改 `useCursorGlow`**。
- `content: none` 必须写在那组 `::after` 规则**之后** —— 两条选择器特性相同，靠源顺序决胜。
  写在前面会被覆盖，而且不报错。

### 光晕的定位要分两套写（包含块陷阱）

> **绝对定位伪元素的包含块是「最近的 positioned 祖先的 padding box」，不是 border box。**

这条几乎坑掉了所有光环：卡片都挂着 `.glass`，带 `1px` 边框，于是 `inset: 0` 让光环对齐
padding box，**比卡片可见的边缘每边内缩 1px**（实测每边 `0.91px`、总差 `1.82px`）。
更麻烦的是 `border-radius: inherit` 继承的是**外圆角**，被用在缩小后的盒子上，圆角处同样错。

```css
/* 有 1px 边框的元素：负 1px 拉回 border box */
.feature-card::after, .stat::after, .contact__card::after,
.more__card::after, .btn::after, .sidebar::after { inset: -1px; }

/* 壳没有边框（border: none），padding box 就是可见边缘 */
.sidebar__edge::after { inset: 0; }
```

`devicePixelRatio` 不是 1 时（本机是 `1.1`，即 110% 缩放）会有残余误差：
Chrome 把 `1px` 边框对齐成 1 个设备像素 = `0.909px` CSS，而 `-1px` 按名义值走，
于是过冲 `0.09px`（总差 `0.18px`）。远小于一个设备像素，可以忽略；
要完全消除就得把 `.glass` 的边框换成 inset 描边（那样 padding box 就等于 border box）。

### 4. 面板本体不铺底膜

`.sidebar` 上挂着 `.glass` 类，而 `.glass` 是**卡片**的玻璃 —— 它自带一层
`linear-gradient(150deg, --glass-1, --glass-2)`（夜间约 `10% → 6%` 的白）。

面板不能要这层白：液态玻璃的体量应该**全部**来自「折射 + 壳上的高光 + 外投影」，
再盖一层白就把背景糊在下面了 —— 看着是一块发白的板，而不是玻璃。
所以桌面端 `.sidebar { background: none }`。

移动端**保留**底膜：顶部横条又窄又扁，没有折射的余地，需要一点底色才有体量。

去掉底膜后，胶囊那层「白膜加倍」的对比才立得起来：面板是 `0`，胶囊约 `20%`（夜间）。

### 性能取舍

位移滤镜要按元素面积重算，而背景光斑是逐帧在动的。所以全站**只挂在侧栏面板这一件上**
（48×352）；`.glass` 卡片仍只用纯模糊 —— 那几张卡片加起来几千平方像素，加上去会掉帧。

**选中胶囊刻意不加折射**，原因是物理性的：胶囊在面板之上，`backdrop-filter` 只能采样
「元素背后已绘制的内容」—— 它采到的就是**面板的背景与那圈 1px 描边**。描边被模糊后
在胶囊内部显成一条亮痕（看着像「胶囊里套了个边栏的框」），而溢到面板外的 9px 又采的是
未模糊的原始背景，里外差出一层。采样顺序绕不过去，所以胶囊改成纯手工叠光：
白膜（两遍 `--glass-1/2` 渐变，等效不透明度 ≈ 0.39）+ 亮边 + 顶部内高光 + 底部内反光 + 内外投影。

## 归档：旧版「更多」的图标形变

`morph.ts` 存的是**旧版**「更多」按钮的形变动画参数：三个圆点 → 连成一条横线 →
整体转 90° → 顶端展出箭头 ↑。

「更多」升格成一个页面之后按钮不再形变，但这套手调坐标值得留，所以归档在这里而不是删掉：
它的两条硬约束（两个状态都绕视图中心、展开态相邻段必须重叠）一旦被无声改坏，
形变会在 0.3s 里跳一下、或者接缝处露一道半透明缝，肉眼极难发现。
`scripts/check-motion.mjs` 里用 3 条断言锁着它。

配套的 `durations.moreMorph` 也留在 `tokens.ts` 里。将来若要复用（例如真做一个折叠菜单），
把 `morph.ts` 的常量接回组件即可。
